## 🔴 치명적

### 1. 평범한 클릭 9번이면 결과가 통째로 사라진다

세션 한도는 분당 10회다 (`web/src/lib/rate-limit.ts` `DEFAULT_SESSION_LIMIT = 10`).
그런데 결과 화면의 **분류 탭 전환이 매번 `/api/match` 를 호출**한다.

| 사용자 동작 | 누적 호출 |
|---|---|
| 결과 진입 | 1 |
| 탭 6개 훑기 | 7 |
| 새로고침 (클라이언트 캐시 소멸) | 8 |
| 탭 2개 더 | **10 → 429** |

**실측: UI 조작 9번, 1분 이내.** 탭 전환은 이미 받아둔 결과를 좁히는 것뿐인데 서버를
왕복하는 게 근본 원인이다.

더 나쁜 건 429 가 났을 때의 화면이다. `results/page.tsx` 에서 `error` 가 `data` 를 덮어써서
**직전까지 보던 카드 14건과 탭이 전부 사라지고** 아래만 남는다:

> 지금은 검색 요청이 많아 잠시 기다려야 합니다. 59초 후에 다시 시도해 주세요. [다시 시도]

문구도 "요청이 많아"라 서버 혼잡으로 읽히는데 실제로는 본인이 눌러서 걸린 것이라
원인을 짐작할 수 없다.

**제안** — (a) 탭 전환을 클라이언트 필터로 돌려 호출을 없앤다. (b) 429 때 기존 `data` 를
유지하고 오류는 배너로만 얹는다. (c) 문구를 "잠시 뒤에 다시 검색할 수 있습니다" 로 바꾼다.

### 2. 답 하나 고치려면 6단계를 통째로 다시 입력 — 실측 13번

"조건 수정" 을 누르면 프로필 쿠키가 멀쩡히 있는데도 **1/6 단계, 나이 칸 빈 값**으로 리셋된다.

| | 조작 수 |
|---|---|
| 처음 입력 완주 | 12 |
| 소득분위 4→8 분위만 바꾸기 | **13** |

고치는 게 처음 입력보다 비싸다. "소득분위를 모릅니다" 로 넣었다가 나중에 알게 되거나,
지역만 바꿔 비교해보는 것이 이 서비스의 가장 자연스러운 재방문 동기인데 그때마다 전체 재입력이다.

**제안** — `/api/profile` 에 GET 을 열어 온보딩 진입 시 기존 값을 채운다. 개인정보 원칙(§8)에
어긋나지 않는다. 이미 그 쿠키로 매칭하고 있기 때문이다.

### 3. 온보딩이 브라우저 히스토리에 없다

6단계가 전부 `useState(step)` 이라 URL 이 `/onboarding` 에서 변하지 않는다. 3단계에서
뒤로가기 / 스와이프 백을 하면 이전 단계가 아니라 **사이트 밖으로 이탈하고 입력이 전부 날아간다.**

```
1단계 나이 입력 → 2단계 성별 → 3단계에서 뒤로가기
  기대: 2단계
  실제: /results (직전 페이지) 로 이탈, 입력 소실
```

모바일에서 스와이프 백은 반사적인 동작이라 이탈률에 바로 꽂힌다.

**제안** — 단계를 `?step=n` 으로 올린다. 6번(탭 URL 상태)과 같은 작업으로 묶인다.

## 🟠 심각

### 4. 못 받는 지원이 받을 수 있는 지원보다 설명이 친절하다

`2e86b35` 에서 `ProgramCard` 의 요약·지원금액을 뺐는데 `NearMissItem` 에는 남아 있다.
같은 화면에서:

| | 카드에 보이는 것 |
|---|---|
| **매칭됨** | 주택도시기금법 시행령 (임차보증금 융자 근거 조항) — 제목뿐 |
| **근접탈락** | 관악구 청년 월세 한시 지원 — *"관악구 거주 청년에게 월세를 6개월간 월 10만원 추가 지원"* |

**대상이 아닌 것만 뭔지 알 수 있다.** 매칭 카드는 제목만 보고 상세로 들어가야 하는데,
상세에는 "대출 원금 최대 2억원 · 이자 연 최대 3% 지원" 이 다 있다. 목록에서 무엇을 고를지
판단할 근거가 없어 7건이면 7번 들어갔다 나와야 하고 — 그러면 1번 항목의 한도에 걸린다.

**제안** — 매칭 카드에 요약 한 줄을 복원한다. 최소한 근접탈락과 같은 수준으로.

### 5. 자유입력이 조용히 결과를 절반으로 깎는다

같은 프로필(41세·자영업·서울 종로구)에 `"오늘 점심 뭐 먹지"` 를 넣었더니 **7건 → 3건.**
사라진 것 중에 대출 4건이 통째로 있었고 탭은 `대출 0` 으로 회색 처리됐다.

화면에는 `찾으시는 것: "오늘 점심 뭐 먹지"` 만 뜨고 **왜 줄었는지, 원래 몇 건이었는지
알려주지 않는다.** 대상인데 몰라서 못 받는 걸 없애자는 서비스가, 문장 한 줄 때문에
대상인 것을 숨긴다.

**제안** — "의도와 무관한 n건 숨김 · 전체 보기" 같은 되돌릴 장치를 붙인다.

### 6. 상세 갔다 오면 탭도 스크롤도 전부 리셋

탭 상태가 URL 에 없어(`/results` 고정) 대출 탭에서 카드 → 뒤로가기 하면 **전체 탭 +
스크롤 최상단**(실측 `scrollY = 0`)이다. 10번째 카드를 보고 있었으면 처음부터 다시 스크롤한다.
결과를 공유하거나 북마크하는 것도 불가능하다.

### 7. 단계가 넘어가도 포커스가 body 에 남는다

1단계에서 Enter → 2단계 진입 시 `document.activeElement` 가 `<body>` 다. 화면 제목이
"성별을 선택해 주세요" 로 바뀌었는데 스크린리더는 아무것도 읽지 않고, 키보드 사용자는
Tab 을 다시 눌러 내려와야 한다. 고령층 접근성을 명시적 목표로 잡고(§8) 글자 크기 슬라이더까지
넣은 서비스에서 아쉬운 자리다.

**제안** — 단계 전환 시 `h1` 에 `tabIndex={-1}` 을 주고 focus 를 옮긴다.

## 🟡 눈에 걸리는 것

### 8. 소득 단계가 어려운 질문을 먼저 한다

1~10분위 버튼 10개가 주(主)고, **정작 사람들이 아는 값**(가구원 수 + 월소득)을 받는
계산기는 아래에 `(선택)` 으로 붙어 있다. 순서가 뒤집혀 있다. 더해서:

- 계산기에 **한쪽만 채우면 "다음" 버튼이 막힌다.** 선택 항목이 진행을 막는데, 경고문은
  계산기 박스 안이라 스크롤해야 보이고 비활성 버튼과 시각적으로 연결되지 않는다.
- 상한 검증이 없다. `999999` 만원 입력 → **"4인 가구 기준액 6,494,738원 대비 약 153971%입니다"**.
  0 하나 더 친 오타가 그대로 통과한다.

### 9. 매칭 근거가 근거처럼 안 읽힌다

`[데모]` 67세 여성 은퇴자에게 **"신혼부부 전용 전세자금대출 — 매칭 근거 · 만 67세 조건에
해당합니다"**, 5세 아동에게 **"근로장려금(EITC) — 별도 자격 제한이 없어 누구나 신청할 수
있습니다"** 가 떴다. 데이터 한계도 섞여 있지만 **문구 자체가 문제다.** "제한이 없어서
나왔다" 는 건 매칭 근거가 아니라 **근거가 없다는 뜻**인데 초록 ✓ 배지로 똑같이 표시된다.
5세 결과 5건 중 3건이 "자격 제한 없음" 이라 개인화된 결과라는 느낌이 사라진다.

**제안** — "자격 제한 없음" 은 초록 배지가 아니라 중립 색으로 낮추고, 정렬에서도 뒤로 민다.

### 10. "법령" 카드가 결과 목록에 섞여 있다

`[데모]` `주택도시기금법 시행령 (임차보증금 융자 근거 조항)` 이 지원금·대출과 같은 층위의
카드로, D-day 와 "상시 접수" 까지 달고 뜬다. 돈을 받으러 온 사람에게 신청할 수 없는 법조문이
결과 한 칸을 차지한다.

### 11. 개발자 지표가 사용자에게 노출

결과 상단 **"응답 4ms · 자유입력은 저장되지 않습니다."** — 뒤 절반은 중요한 안내인데
앞의 `응답 4ms` 가 붙어서 같이 기술적인 문구로 보인다.

### 12. 좁은 화면에서 벤 다이어그램 라벨이 겹친다

390px 에서 가운데 "내 것" 흰 박스가 양쪽 원의 라벨 위에 얹혀 `내가 대상인가` 의 끝 글자와
`내가 찾는 것인가` 의 첫 글자가 가려진다. `IntersectionDiagram.tsx` 주석이 이미 경고하는
구간이다 — *"상한이 걸리는 구간에서는 라벨만 커지므로 안쪽 글자를 두 줄 이내로 짧게 유지해야 한다"*.

> 참고 — 점검 중 이 다이어그램이 "빈 박스로 보인다" 고 잘못 판단한 적이 있는데,
> 풀페이지 스크린샷에서 스크롤 구동 애니메이션(`animation-timeline: view()`)이 진행되지 않아
> 생긴 캡처 아티팩트였다. 실제로 스크롤하는 사용자에게는 불투명도 1 로 또렷하게 보인다.

### 13. 잔가지

- 헤더 돋보기 아이콘이 **클릭해도 아무 일도 일어나지 않는다** (글자 크기 슬라이더의 장식).
  검색 버튼으로 오독되는데 이 서비스에는 검색창이 없다.
- `보건복지부 고시 확인` 링크가 **125 × 14px** — WCAG 2.5.8 최소 24px 미달. 고령층 대상에서는 특히.
- `[데모]` "AI 안내를 불러오지 못했지만…" 경고 배너가 결과 **최상단**에 뜬다. 실패해도 카드는
  정상이라는 설계인데, 위치 때문에 사용자는 결과보다 "실패" 를 먼저 본다.

## 문제 없었던 것

빠짐없이 확인했으나 결함이 없던 것들. 회귀 때 참고용으로 남긴다.

| 항목 | 결과 |
|---|---|
| 나이 경계값 `0 / 120 / 121 / -5 / 3.5 / 문자 / 999999999` | 전부 정확히 처리, `role="alert"` 안내 정상 |
| 글자 크기 22px 에서 랜딩·온보딩·결과 | **가로 스크롤 0** (`scrollWidth == clientWidth`) |
| 저장된 큰 글씨로 재방문 | 깜빡임 없음 — SSR 처리 정상 |
| 시·도 17개 전부 | 시·군·구 목록 존재 (세종 1, 경기 47) |
| 자유입력 200자 초과 | `maxLength` 로 절삭 + 카운터 정상 |
| 404 · 없는 상세(`/programs/99999`) | 안내 화면 정상 |
| 프로필 없이 `/results` 직접 접근 | 단계 안내 + 입력 유도 정상 |
| 랜딩 텍스트 대비 (WCAG AA) | **미달 0건** |
| 라디오 선택 버튼 터치 영역 | `label` 이 감싸 충분함 |

## 우선순위 제안

투입 대비 체감이 큰 순서다.

1. **1번** — 탭 전환을 클라이언트 필터로 + 429 때 기존 결과 유지. 가장 흔한 경로에서 서비스가 죽는다.
2. **2번** — 프로필 쿠키로 온보딩 프리필. 재방문 비용을 13번에서 2~3번으로 줄인다.
3. **4번** — 카드에 요약 한 줄 복원. 되돌리는 한 줄짜리 변경이다.
4. **3번 + 6번** — 단계와 탭을 URL 로 올린다. 두 개가 같은 작업이다.
