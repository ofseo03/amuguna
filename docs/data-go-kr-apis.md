> 조사일 2026-08-11. [SPEC.md §3.3 소스 목록](../SPEC.md)의 후보를 포털에서 재확인하고,
> **대회 주제("맞춤형 금융 AI 서비스")에 직결되는데 SPEC에 없던 금융 API를 추가로 찾은 결과.**

## 검증 한계 (먼저 읽을 것)

조사 환경에서 `www.data.go.kr` · `apis.data.go.kr` · `api.odcloud.kr` · `finlife.fss.or.kr` ·
`bizinfo.go.kr` · `youthcenter.go.kr` 이 **전부 네트워크 차단**이라 포털 페이지를 직접 열지 못했다.
아래 내용은 **검색엔진이 수집한 포털 페이지 제목·설명 스니펫**으로 교차 확인한 것이다.

| 확인 수준 | 의미 |
|---|---|
| **데이터셋 실재** | 포털 페이지 제목·기관명·설명이 검색 결과로 확인됨 → ID와 존재는 신뢰 가능 |

→ **키 발급 후 실호출로 확정한다** (SPEC §12 W1 항목 그대로 유효).

## 2. 신규 발견 — 금융 축 API (SPEC 미기재, 대회 주제 직결)

SPEC의 금융 소스는 금감원 finlife 1종뿐이었다. **포털 안에 서민·정책금융 상품 API가 따로 있다.**
대회 세부주제가 "청년층 자산 형성 및 고령층·장애인 **포용적 금융서비스**"(SPEC §0)인 만큼
finlife(시중 금융상품)보다 이쪽이 주제 적합도가 높다.

### 2.1 최우선 — 자격 축이 정형 필드로 올 가능성이 가장 높은 소스

| 데이터셋 ID | 명칭 | 왜 중요한가 |
|---|---|---|
| [`15094787`](https://www.data.go.kr/data/15094787/openapi.do) | **금융위원회_서민금융상품기본정보** | 취급기관별 **서민금융 대출상품·자산형성상품·사회적금융** 상품의 명칭 / **지원대상** / 금리 / 대출한도 / 상환방식 / 취급기관을 통합 제공. 오퍼레이션 1종(서민금융한눈에 정보 조회). **"지원대상"이 필드로 오면 §6 정규식 파싱을 거치지 않고 바로 `eligibility_rules`에 넣을 수 있다** — SPEC §12-1 파싱 리스크의 직접적 헤지 |
| [`15106208`](https://www.data.go.kr/data/15106208/openapi.do) | **서민금융진흥원_대출상품한눈에 정보 서비스** | 상품명 / 대출한도 / 금리구분 / **자금용도** / 총 대출기간 / 취급기관. 설명에 **"자금용도·지원대상 기준으로 정부·정책금융기관·지자체 상품을 검색"** 이 명시 — 우리 의도 축(§7.3)과 구조가 같다 |

두 건은 같은 "서민금융 한눈에"(서금원 운영) 원천을 공유할 가능성이 높다.
**W1에 두 응답을 실제로 받아 필드를 비교하고 하나로 정리할 것** — 중복 적재 시 같은 상품이 카드 2장으로 나온다.

### 2.3 배경

금융위원회가 2020년부터 금융공공데이터를 포털에 개방 중이며, **10개 주제 / 102개 오픈API / 335개 테이블**

본 서비스 범위 밖이다.

## 5. W1에 실호출로 확정할 것

1. **`15094787` / `15106208` 필드 비교** — 원천 중복 여부, "지원대상"이 코드값인지 서술형인지.
   코드값이면 §6 파싱 파이프라인을 건너뛰는 경로를 따로 둔다
2. `15090532` 오퍼레이션명이 문서상 `NationalWelfarelistV001` / `NationalWelfaredetailedV001` 인데
   **실제 호출 경로(호스트 + 서비스 경로)는 미확인** — Swagger에서 확정
3. `15119396` "고객특성별 추천"의 요청 파라미터가 우리 프로필 5필드(§5)와 어떻게 매핑되는지
4. 중앙부처복지 **운영계정 전환 신청**(개발계정 100회/일) — SPEC §3.2 그대로, Day 1
5. 금융 API 5종의 **일일 트래픽 한도** — 포털 페이지를 열지 못해 전부 미확인
6. `15143273`(신) 활용신청 — `15088883`(구)와 혼동 금지
